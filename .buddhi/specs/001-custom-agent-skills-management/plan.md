## Summary

Implement a new top-level CLI command `buddhi skills` with pluggable, on-demand skill management for Google Antigravity agent harnesses.

Key deliveries:
1. **Discoverability**: `buddhi skills` without flags lists all registered custom skills, their descriptions, and their flags in a formatted Rich table.
2. **Selective Installation**: `buddhi skills --repo-to-skill` provisions the Antigravity-optimized `repo-to-skill` skill into `<project_root>/.agents/skills/repo-to-skill/`. Includes overwrite protection and `--force` support.
3. **Dedicated Template Isolation**: Packages custom skills under `src/buddhi/templates/custom_skills/` rather than `src/buddhi/templates/agents/skills/`, ensuring that `buddhi init` does NOT eagerly scaffold them.
4. **Python-Native Runner & Cross-Platform Execution**: Replaces upstream bash scripts with a pure Python 3.10+ repository analyzer (`analyze_repo.py`) executable both directly and via `buddhi skills run repo-to-skill <target> [--json]`.
5. **Unified Registry**: A centralized `SkillRegistryEntry` architecture enabling future skills to be registered with zero structural changes to the CLI or installer plumbing.

## Architectural & Module Design

### 1. Centralized Skills Registry (`src/buddhi/skills/registry.py`)

```python
from dataclasses import dataclass
from typing import Callable, Optional

@dataclass(frozen=True)
class SkillRegistryEntry:
    name: str                        # "repo-to-skill"
    flag: str                        # "--repo-to-skill"
    title: str                       # "Repo to Skill Generator"
    description: str                 # "Turn any GitHub repo or directory into an Antigravity agent skill"
    template_pkg: str                # "buddhi.templates.custom_skills.repo_to_skill"
    target_dir_name: str             # "repo-to-skill"
    runner: Optional[Callable] = None # Function called when running `buddhi skills run repo-to-skill`
```

An extensible registry table `SKILL_REGISTRY: dict[str, SkillRegistryEntry]` will hold all available skills. Future skills simply register here and place their templates in `templates/custom_skills/`.

### 2. Selective Installer (`src/buddhi/skills/installer.py`)

- `install_skill(entry: SkillRegistryEntry, target_root: Path, force: bool = False) -> SkillInstallReport`
  - Resolves destination path: `target_root / ".agents" / "skills" / entry.target_dir_name`.
  - Checks if destination already exists:
    - If exists and `not force`: returns report with `skipped=True` and a helpful warning.
    - If `force`: overwrites existing files with clean template versions.
  - Loads resources from `entry.template_pkg` using `importlib.resources`.
  - Uses `atomic_write_bytes` or `sync_template_tree` (adapted for specific directory) to write files safely.
  - Ensures parent directories (`.agents/skills/`) exist.

### 3. CLI Command (`src/buddhi/commands/skills.py`)

- `skills_app = typer.Typer(help="Manage and execute custom agent skills.", invoke_without_command=True)`
- Root callback / command handler:
  - If no flags provided and no subcommand invoked: displays Rich table with:
    - Skill Name
    - Installation Flag
    - Description
  - If `--repo-to-skill` is passed: calls `install_skill` for `repo-to-skill`.
  - Supports `--path` (defaults to `.`) and `--force` (`-f`).
- Subcommand `run`:
  - `buddhi skills run <skill-name> <target> [--json]`
  - Dispatches to the skill's registered `runner`.

### 4. Cross-Platform Repository Analyzer (`src/buddhi/skills/repo_to_skill.py` & template `analyze_repo.py`)

- Pure Python implementation:
  - Analyzes repository root (either a cloned local dir or shallow clones a remote GitHub URL to a temp directory).
  - Inspects `README.md`, docs directories, example folders, and project manifests (`pyproject.toml`, `package.json`, `Cargo.toml`, `go.mod`, etc.).
  - Classifies project type: CLI tool, library, framework, or service.
  - Detects entry points, primary commands, and environment/configuration requirements.
  - Emits JSON or formatted summary for agent consumption.
